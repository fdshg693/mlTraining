# data/ 配下のデータの取り扱い注意点

baseballsavantのリーダーボードCSVを扱う際に見つかった、値の意味を誤解しやすい点をまとめる。新しい注意点が見つかったら追記する。

## 球種別フィールドのNaNは「投げていない」であって欠損ではない

`n_sl_formatted`（Slider %）のような球種使用率、および`sl_avg_speed`/`sl_avg_spin`/`sl_avg_break*`のような球種別の平均球速・回転数・変化量フィールドは、その投手がシーズン中に該当球種を1球も投げていない場合にNaNになる。統計的な欠損（本来値はあるが取得できなかった）ではなく、「該当なし」を意味するNaNである。

このため、複数の球種別フィールドを特徴量として使う際に素直に`dropna()`すると、**全ての対象球種を投げた投手だけ**に標本が偏る。実例（2026年投手、4シーム/シンカー/スライダー/カーブ/チェンジアップ/カッターの6球種使用率+球速+回転数+イニング数+登板数+ERAの11列）では、305行 → `dropna()`後は40行まで減った。

対処方針（フィールドの種類によって異なる）:
- **使用率（`n_*_formatted`）**: NaN = 0%として扱ってよい。`fillna(0)`してから他の列のdropnaを行う（[mlb/analysis/prediction/compare_models.py](../../analysis/prediction/compare_models.py)を参照）。
- **平均球速・回転数・変化量（`*_avg_speed`/`*_avg_spin`/`*_avg_break*`）**: 「投げていない球種の平均球速」は定義できないため、0埋めは意味的に不適切。対象を「その球種を一定以上投げた投手」に絞る、その列自体を特徴量から外す、など分析の目的に応じて個別に判断する。安易な`fillna(0)`はモデルに誤った信号（0mph/0回転）を与えるため避けること。

## シーズン途中の年を他の年と混ぜて学習・評価に使わない

`--min-sample`（規定投球回など）はシーズンが終了しているかどうかに関わらず「その時点までの」投球回・打席数を基準に対象を絞る。シーズン途中の年（例: 実行時点で進行中の年）のリーダーボードは、完了済みシーズンに比べて対象人数が少なく（例: 2026年は8月時点でqualified基準の投手が完了年より少ない）、ERA等の分布も途中経過にすぎない。[mlb/analysis/prediction/year_shift.py](../../analysis/prediction/year_shift.py)のように複数年をtrain-dev/testとして扱うスクリプトでは、進行中の年を安易に他の完了済みシーズンと同列に混ぜない（testとして使う場合も、それが「シーズン途中の値」であることを認識した上で解釈する）。

## `min_sample`（`--min-sample`）はNaNの発生源を減らせるが無くせない

`fetch_leaderboard.py`の`--min-sample`は投球回数・打席数の下限であり、個々の球種を一定数投げたかどうかは保証しない。`--min-sample 40`のように上げても、特定の球種を全く投げない投手（例: カーブを持たない投手）は依然として存在し、該当列はNaNのままになる。
